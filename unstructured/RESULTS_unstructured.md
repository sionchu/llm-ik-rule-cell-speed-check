# 비정형 픽앤플레이스: 룰(티칭+비전 보정) vs LLM(IK 후보 선택) (2026-11-12)

질문: 박스 크기·자세·파손 위치가 매번 다르고 목적지가 15곳일 때, 사람이 티칭한 룰과 "코드가 IK·충돌 검증한 후보 중 LLM이 고르는" 방식은 얼마나 다른가.

## 구성 (전부 가정 셀, 시뮬 계산)
- 로봇 RB16-900E 기구학, Lula IK(드릴 셀 cellkit 재사용), 점 샘플 충돌 검사(로봇 링크·흡착 툴·들고 있는 박스 vs 벨트·레일·옆 박스·투입구 벽). 물리·렌더 없음. 다른 프로젝트 Isaac 프로세스와 겹치지 않게 Isaac Python만 따로 실행(GPU 미사용).
- 박스 40개(시드 2027): 크기 20~50 × 15~40 × 8~35 cm, 1~20 kg, 방향 ±90°, 위치 랜덤. 파손: 없음 14, 찢김 11, 젖음 13, 둘 다 2. 옆 박스 22개. 목적지 15곳(슈트 12 + 재스캔·수동·불량).
- 흡착 성공 조건(가정): 컵(반지름 4.5 cm)이 면 안, 찢김·젖은 자국에 안 닿음, 유지 토크 ≤ 15 N·m.
- 이미지: 위에서 본 합성 그림(PIL), 후보 흡착점 0~8을 표시. Isaac 렌더 아님.

| 방식 | 하는 일 |
|---|---|
| 룰(티칭 + 비전 보정) | 비전이 박스 위치·각도만 보정. 박스 중심을 잡고, 사람이 티칭한 이동 높이(1.20 m)와 투입 자세로 이동. 실행 중 충돌 검사 없음 |
| 기하 룰 | 후보 54개(흡착점 9 × 손목 2 × 이동 높이 3)를 IK + 충돌 + 토크로 걸러 가장 빠른 것. 이미지(파손)는 안 봄 |
| LLM 선택 | 같은 유효 후보 목록 + 이미지를 Opus(low)에 주고 하나 고르게 함. 유효 후보의 흡착점이 2곳 이상인 31건만 호출 |
| 정답 상한 | 실제로 안 떨어지는 유효 후보 중 가장 빠른 것 |

## 결과 (40개)
| 방식 | 자동 처리 성공 | 실패 내역 | 성공 박스 평균 동작 | 판단 시간(박스당) | 박스당 LLM 비용 |
|---|---|---|---|---|---|
| 룰(티칭 + 비전 보정) | 12 | 낙하 19, 충돌 5, IK 실패 4 | 7.64 s | IK 0.01 s | 0 |
| 기하 룰 | 19 | 낙하 17, 유효 후보 없음 4 | 5.85 s | 후보 계산 55 s* | 0 |
| **LLM 선택** | **23** | 낙하 12, 유효 후보 없음 4, 잘못된 id 1 | **5.70 s** | 후보 계산 55 s* + Opus 4.5 s | CLI $0.048 / 직접 API 약 $0.016(추정) |
| 정답 상한 | 23 | 안전한 후보 없음 17 | 5.70 s | — | — |

\* 후보 계산 55 s(중앙값)는 CPU Python 프로토타입(후보 54개 × 7구간 × 충돌 샘플) 값. 실제 라인용 플래너(GPU 일괄 계산 등)로 얼마나 줄어드는지는 NOT_RUN. 비전 위치 추정 시간은 세 방식 공통이라 빠짐.

- **안전한 후보가 있을 때 고르는 정확도**: 고를 게 있던 31건 중 안전한 점이 존재한 21건에서 LLM 21/21, 기하 룰 17/21. LLM은 정답 상한(23)과 같고, 고른 후보의 동작 시간도 상한과 같음(5.70 s).
- **룰(티칭)은 비정형에서 무너짐**: 파손 없는 박스는 10/14 성공, 파손 박스는 2/26. 충돌 5건은 티칭한 이동 높이로 옮기다 큰 박스가 옆 박스·투입구 벽에 닿은 경우(실행 중 검사 없음 → 실제면 정지·파손).
- **동작 시간**: 둘 다 성공한 12개에서 룰 7.64 s → LLM 5.72 s(−25%). 이 이득은 LLM이 아니라 후보 생성(낮은 이동 높이·짧은 손목 회전)에서 나옴. 기하 룰도 5.72 s.
- **LLM이 진 12건**: 안전한 점이 아예 없는 박스. "수동 처리" 선택지를 안 줘서 아무거나 골랐음 → 선택지에 MANUAL을 넣으면 낙하 대신 수동으로 빠짐(재실행 NOT_RUN).

## 정리
- 비정형일수록 차이가 커짐: 자동 처리 12 → 23(/40). 단 LLM이 IK를 직접 푼 게 아니라, **코드가 IK·충돌을 검증한 후보 중 LLM이 이미지를 보고 고름**. 역할 분리: 후보·IK·충돌 = 코드, 의미 판단(파손 회피) = LLM.
- 속도 이득(동작 −25%)은 후보 최적화 몫이고, LLM은 박스당 약 4.5 s(서버 시간)를 더함. 이전 박스 동작(5.7 s) 중에 다음 박스를 고르면 사이클에 안 보이는 크기. 후보 계산 55 s는 프로토타입이라 실사용 전 최적화 필수.
- 룰도 파손 검출기(예: v3 색 특징)를 붙이면 이 합성 셋에선 상한에 갈 수 있음. LLM의 이득은 새 파손 유형마다 검출 룰을 따로 짜지 않아도 된다는 점.
